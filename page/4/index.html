Cookie

 spawn2pwn published on 2026-04-26 included in Web and NCKUCTF

A playful challenge where your identity is determined by a cookie. Can you prove to the server that you are the true Cookie Monster?

TL;DR
Cookie is a web security challenge that demonstrates the risks of unverified, client-controlled cookies. The server sets an initial cookie user=anonymous and checks if the cookie value matches cookie_monster. Because cookies are completely under client control and lack digital signatures (such as HMAC), modifying the cookie header to user=cookie_monster grants unauthorized access and leaks the flag.

Dig

 spawn2pwn published on 2026-04-26 included in Web and NCKUCTF

A web utility that executes the dig command to query domain records. Can you break out of the command syntax and hijack the shell?

TL;DR
Dig is a web security challenge that explores OS Command Injection. The application takes a domain name from a POST parameter and executes system("dig '" . $_POST['name'] . "';") . Because the parameter is placed inside single quotes without proper escaping, an attacker can supply a closing single quote followed by arbitrary shell commands ( '; bash -c "..."; # ) to execute arbitrary commands and retrieve the flag.

LFI

 spawn2pwn published on 2026-04-26 included in Web and NCKUCTF

A simple PHP file reader with dynamic inclusion. Can you bypass standard execution flow to inspect the protected flag?

TL;DR
LFI is a web security challenge that explores Local File Inclusion in PHP. The target file ( flag.php ) contains an exit() statement that terminates script execution before any output is generated when included normally. By using PHP’s stream filter wrapper ( php://filter/convert.base64-encode/resource=... ), the source code is base64-encoded prior to interpretation, preventing execution and leaking the flag comment.
